**Project Title:** AI-Powered Continuous Behavioral Biometrics

---

**1. System Architecture & Data Flow**

```
[User Interaction] 
       │ (MouseMove, Click, KeyPress)
       ▼
[JS Telemetry Scraper] ──> Extracts 32 statistical features every 2–3s
       │
       ▼
[Siamese Network (128D Encoder)] ──> Converts features into 128D Behavioral Vector
       │
       ▼
[LightGBM Anomaly Scorer] ──> Compares live vector against stored User Gallery
       │
       ▼
[Security Action Engine] ──> Anomaly Score < 0.8: Allow
                             Anomaly Score ≥ 0.8 (for 3 cycles): Trigger 2FA / Lockout

```

---

**2. Frontend Telemetry & Feature Engineering (JS Lead)**

* **Raw Event Capture:** Listen to `mousemove`, `mousedown`, `mouseup`, `keydown`, `keyup`, and `wheel`.
* **Sampling Window:** Batch and process events every **$2\text{--}3\text{ seconds}$**.
* **32 Extracted Features:**
* *Kinematics:* Mean/Max Velocity, Acceleration, Jerk (3rd derivative of position).
* *Geometry:* Path curvature, straight-line efficiency ratio ($d_{\text{direct}} / d_{\text{actual}}$), angular direction changes.
* *Rhythm:* Click dwell time (`mouseup` - `mousedown`), keypress flight time, idle-to-movement ratio.
* *Tremor (Spectral):* Fast Fourier Transform (FFT) frequency distribution of micro-movements.



---

**3. AI/ML Engine (ML Lead)**

* **Stage 1: Siamese Neural Network (Feature Encoder)**
* **Input Size:** 32 engineered features.
* **Architecture:** `Input(32) -> Dense(64, ReLU) -> Dense(128, ReLU) -> Dense(128, Linear) -> L2 Norm`.
* **Output:** $128\text{D}$ normalized embedding vector.
* **Pre-Training:** Train once using **Triplet Loss** on public benchmark data (*Balabit Mouse Dynamics Dataset*) to learn human movement distances.


* **Stage 2: LightGBM Anomaly Classifier**
* **Inputs:** Live $128\text{D}$ vector + calculated Cosine/Euclidean distances relative to the user's gallery.
* **Training:** Fits in $<50\text{ms}$ upon user login using 30 user gallery vectors (Class 0) vs. 150 background dataset samples (Class 1).



---

**4. User Lifecycle & Application Logic**

| Phase | Duration | Action |
| --- | --- | --- |
| **1. Cold Start (Enrollment)** | First $30\text{--}60\text{s}$ | Collect $15\text{--}30$ valid $128\text{D}$ vectors. Store them in memory as the user's **Baseline Gallery**. |
| **2. Continuous Scoring** | Ongoing ($2\text{s}$ intervals) | Generate live $128\text{D}$ vector $\rightarrow$ Query LightGBM $\rightarrow$ Produce Risk Score ($0.0\text{--}1.0$). |
| **3. Threat Escalation** | $3\times$ consecutive spikes | If Risk Score $> 0.80$ three times in a row, trigger step-up authentication (2FA modal) or terminate session. |

---

FILE 2

Integrate navigation metrics directly into the main feature vector using **Stateful Concatenation**.

Building a separate sub-model creates unnecessary system complexity and network overhead. Because physical telemetry fires continuously (every 2–3 seconds) while navigation events fire asynchronously (only on tab clicks), maintain a stateful **"Navigation Snapshot"** in memory. Every time the 2-second telemetry window closes, append the latest navigation values to the vector before passing it to the model.

---

### Integration Architecture: Stateful Concatenation

```
[Mouse/Keyboard Events] ──> Computed every 2s ──> [32 Physical Features]  ──┐
                                                                           ├──> [38 Combined Features] ──> LightGBM
[Tab Navigation Events] ──> State updated live ──> [ 6 Nav Features ]     ──┘

```

By passing all 38 features into a single LightGBM model, the decision trees can learn cross-domain rules—such as detecting when a user navigates to an unexpected tab (*high navigation surprise*) while simultaneously moving the mouse with unusual speed (*high kinematic deviation*).

---

FILE 3

To analyze dashboard navigation, you are dealing with **Time-Aware Discrete Sequences** (discrete tab choices paired with continuous time durations).

Rather than building a complex standalone neural network that slows down your dashboard, the cleanest hackathon solution is to convert navigation workflows into a small vector of statistical features and feed them directly into your existing **LightGBM / GBDT Risk Engine**.

---

### 1. How to Turn Navigation into Valuable Numbers

A raw navigation log looks like this:
`[Tab: Home (12s)] -> [Tab: Analytics (3s)] -> [Tab: User Settings (45s)]`

You convert this sequence into numerical features using three mathematical techniques:

#### A. Transition Probability (Markov N-Gram Matrix)

Assign every tab an ID (`Home=0`, `Analytics=1`, `Settings=2`, `Billing=3`). Track how often the legitimate user transitions from Tab $A$ to Tab $B$.

* **Transition Matrix $P(i \to j)$:** If the real user goes `Home -> Analytics` $80\%$ of the time, $P(0 \to 1) = 0.8$.
* **Transition Surprise Score:** When a user navigates from Tab $i$ to Tab $j$, calculate the "Surprise":

$$\text{Surprise} = -\log_2(P(i \to j))$$

*(If an attacker jumps straight from `Home -> Billing`—a path the real user never takes—$P(0 \to 3) \approx 0.01$, causing the Surprise Score to spike).*

#### B. Dwell Time Z-Score (Timing Anomalies)

People navigate dashboards with specific goals. An employee who knows the system spends **$2\text{ seconds}$** finding a setting; an attacker searching for sensitive data spends **$30\text{ seconds}$** reading the tab.

* Calculate the historical mean ($\mu$) and standard deviation ($\sigma$) of the user's dwell time on each specific tab.
* For every tab visit, compute the Z-score:

$$Z = \frac{\text{DwellTime} - \mu_{\text{tab}}}{\sigma_{\text{tab}}}$$

#### C. Sequence Entropy (Navigational Chaos)

Calculate the Shannon Entropy of tab visits over a rolling 5-step window to measure how "random" or erratic their navigation path is:

$$H(X) = -\sum_{i=1}^{N} P(x_i) \log_2 P(x_i)$$

* **Legitimate User:** Low entropy (follows repetitive, structured workflows).
* **Attacker/Scraper:** High entropy (clicks tabs erratically looking for vulnerabilities).

---

### 2. The Complete Navigation Feature Vector

For every tab click, your JS telemetry script generates a **6-feature numeric vector**:

| Feature Name | Description | Example Value |
| --- | --- | --- |
| `current_tab_id` | Integer ID of current view | `2` (`Settings`) |
| `prev_tab_id` | Integer ID of previous view | `1` (`Analytics`) |
| `transition_prob` | Historical probability of moving `prev_tab` $\to$ `current_tab` | `0.85` |
| `dwell_time_zscore` | Z-score of time spent on the *previous* tab | `+0.4` (Normal) |
| `sequence_entropy` | Entropy of the last 5 tab visits | `1.2` |
| `out_of_order_flag` | Binary indicator ($1$ if transition probability $< 0.05$, else $0$) | `0` |

---

### 3. What Model Should You Design?

#### Option A: Feed Into Existing LightGBM (Recommended for Hackathon)

Append these 6 navigation features directly to your 32-feature mouse/keyboard telemetry vector. Your LightGBM model now evaluates physical habits **and** workflow logic simultaneously in a single, fast sub-millisecond pass.

#### Option B: Dedicated Sequence NN (Embedding + GRU)

If your team wants a dedicated neural network specifically for navigation sequence modeling:

```
[Tab ID Sequence] ──> Embedding Layer (8D) ──┐
                                             ├──> Concatenate ──> GRU Layer (32 units) ──> Dense (1) ──> Anomaly Score
[Dwell Times & Zs] ──────────────────────────┘

```

1. **Embedding Layer:** Maps discrete Tab IDs (e.g., Tab 0 to 20) into an 8-dimensional dense vector space.
2. **Concatenation:** Combines the Tab Embedding vector with continuous features (`dwell_time`, `z_score`).
3. **Gated Recurrent Unit (GRU):** A lightweight recurrent layer (faster than LSTM) that processes the last 5 to 10 tab steps to detect sequential order anomalies.

---

### Summary Recommendation

Start by computing **Transition Probabilities + Dwell Time Z-scores** in JavaScript. Append them directly to your existing LightGBM vector. This gives you high-accuracy workflow detection without adding the engineering complexity of a second recurrent neural network.
